## この章でやること

ここからは、frontend(Next.js)をECSにデプロイしていきます。大まかな流れはバックエンドのときと同様ですが、こちらについてもひとつずつ説明していきます。

まずは、frontend用のECSに使用するセキュリティーグループの作成から始めていきます。

> 📍 **デプロイ全体フロー（現在地）**  
> ① VPC → ② サブネット → ③ IGW → ④ ルートテーブル → **⑤ セキュリティグループ(frontend)** → ⑥ RDS → ⑦ ECR → ⑧ コード準備 → ⑨ タスク定義 → ⑩ ALB → ⑪ サービス起動 → ⑫ CD自動化

### backendとの違い

frontendのセキュリティグループはbackendとほぼ同じ設定（HTTP許可）です。backendではRDS用SGも一緒に作成しましたが、frontendはECS用のSGのみ作成します。frontendはDBに直接接続しないためRDS用SGは不要です。

## 手順

VPCダッシュボードから「セキュリティグループ」にアクセスし、「セキュリティグループを作成」を押下します。

![](https://static.zenn.studio/user-upload/debe6ee4c31c-20230528.png)

#### 基本的な詳細

| 項目 | 値 |
| --- | --- |
| セキュリティグループ名 | zenn-clone-ecs-frontend-security-group |
| 説明 | 任意 |
| VPC | zenn-clone-vpc |

![](https://static.zenn.studio/user-upload/11ee362c7ff0-20230528.png)

#### インバウンドルール

全てのHTTP通信を許可します。

| タイプ | ソース |
| --- | --- |
| HTTP | Anywhere-IPv4 |
| HTTP | Anywhere-IPv6 |

> 💡 **backendと同様、HTTPのみでよい理由**  
> frontendもALBの内側に配置するため、HTTPS終端はALBが担います。ECS（Next.js）はHTTP(80番ポート)で受け付ければ十分です。

![](https://static.zenn.studio/user-upload/56ebd908f5d2-20230907.png)

#### アウトバウンドルール

デフォルトのままでOKです（念のため以下の画像のようになっていることを確認してください）。

![](https://static.zenn.studio/user-upload/86bb14ec182d-20230528.png)

↓

「セキュリティグループを作成」を押下し、セキュリティグループが正常に作成されたらOKです！
