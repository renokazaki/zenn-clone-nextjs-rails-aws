## この章でやること

アプリケーションをデプロイするVPCを作成します。

> 📍 **デプロイ全体フロー（現在地）**  
> **① VPC** → ② サブネット → ③ IGW → ④ ルートテーブル → ⑤ セキュリティグループ → ⑥ RDS → ⑦ ECR → ⑧ コード準備 → ⑨ タスク定義 → ⑩ ALB → ⑪ サービス起動 → ⑫ CD自動化

### なぜ最初にVPCを作るのか

後続の**すべてのAWSリソース**（ECS・RDS・ALBなど）はVPCの内部に作成します。VPCなしには何も始まりません。「自分専用のプライベートなネットワーク空間」を確保することが、AWSデプロイの絶対的な第一歩です。

なお、**VPCを作成しただけではインターネットとの通信はできません**。この後の章でIGW・ルートテーブル・セキュリティグループを追加して、ようやく外部通信が可能になります。

## VPCとは？

**VPC（Virtual Private Cloud）** とは、AWSクラウド内にプライペートな仮想環境を構築するためのサービスです。

イメージとしては、AWSが全世界向けの提供している広大な土地（クラウド）のうち、一部を自分の土地として申請しているような感じです。

今後、この自分のものとなった土地の中に、オリジナルの家を建てていく（アプリをデプロイする）ことになります。

## 手順

検索窓からVPCにアクセスし、「VPCを作成」を押下します。

![](https://static.zenn.studio/user-upload/e60f75f03cf6-20230514.png)

↓

以下項目を設定し、「VPCを作成」します。

| 項目 | 値 |
| --- | --- |
| 作成するリソース | VPCのみ |
| 名前タグ | zenn-clone-vpc |
| IPv4 CIDR ブロック | IPv4 CIDR の手動入力 |
| IPv4 CIDR | 10.0.0.0/16 |
| IPv6 CIDR ブロック | IPv6 CIDR ブロックなし |

> 💡 **`10.0.0.0/16` の意味**  
> - **CIDRとは**：IPアドレスの範囲を表す記法。`/16` は「先頭16ビットを固定」を意味し、2¹⁶ = **65,536個**のIPアドレスを確保できる  
> - **なぜ広い範囲を取るか**：後続のサブネットに細かく割り振るため。VPCは余裕を持って広めに確保するのが定石  
> - **なぜ `10.0.x.x` か**：RFC 1918 で定義された**プライベートIPアドレス帯**（インターネット上に存在しない番号帯）のため外部と衝突しない安全な選択
| テナンシー | デフォルト |

![](https://static.zenn.studio/user-upload/8b27696b4725-20230514.png)

↓

VPCが正常に作成されればOKです。

![](https://static.zenn.studio/user-upload/32a672e4cd8a-20230514.png)
