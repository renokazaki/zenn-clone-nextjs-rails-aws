## この章でやること

Dockerfile.prod に基づいてビルドした railsコンテナとnginxコンテナを、AWS ECR にプッシュします。

> 📍 **デプロイ全体フロー（現在地）**  
> ① VPC → ② サブネット → ③ IGW → ④ ルートテーブル → ⑤ セキュリティグループ → ⑥ RDS → **⑦ ECR** → ⑧ コード準備 → ⑨ タスク定義 → ⑩ ALB → ⑪ サービス起動 → ⑫ CD自動化

### なぜECRが必要か

ECSはDockerイメージをどこかから取得してコンテナを起動します。ECRはそのイメージの「置き場所」です。DockerHubなど他のレジストリも使えますが、ECRはAWSアカウント内のプライベートレジストリであり、**IAM認証でアクセス制御**できる点と、**ECSとのネットワーク的な近さ**（同一リージョン内転送なので高速・低コスト）が理由で採用します。

## ECRとは？

**ECR(Elastic Container Registry)** は、Dockerコンテナを保存しておけるリポジトリです。

ローカルでDockerコンテナをビルドし、ECRに対してプッシュします。これを、ECSでデプロイして運用する、という流れとなっていきます。

## 📋 この章を始める前の前提条件

- [ ] `aws --version` が正常に返ってくる（AWS CLIインストール済み）
- [ ] `aws configure` でIAMユーザーの認証情報が設定済み（「ターミナルからAWSにアクセス」完了）
- [ ] `rails/Dockerfile.prod` と `nginx/Dockerfile.prod` が作成済み（「backendのデプロイ準備」完了）
- [ ] `rails/config/master.key` が存在している（gitignoreされているが手元にあること）

> 💡 **なぜ「プライベート」か**  
> プライベートにすることで、IAM認証を持つECSタスク実行ロールとGitHub ActionsのIAMユーザーだけがイメージをpull/pushできます。パブリックにするとインターネット上の誰でもイメージを取得できてしまい、コードの流出リスクがあります。

> 💡 **4ステップの意味**  
> ①認証：AWSのIAM認証情報でECRへのログイン  
> ②ビルド：本番用Dockerfileからイメージを作成

> ④プッシュ：タグ付きイメージをECRにアップロード  
> この4ステップは後のCD（GitHub Actions）でも自動化される手順と同じです。

## ⚠️ よくあるエラーと対処法

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `no basic auth credentials` | ECRへの認証が済んでいない | プッシュコマンドの手順1（`aws ecr get-login-password ...`）を先に実行する |
| `denied: Your authorization token has expired` | 認証トークンの有効期限切れ（12時間） | 手順1の認証コマンドを再実行して新しいトークンを取得する |
| `Cannot connect to the Docker daemon` | Dockerが起動していない | Docker Desktopを起動してから再試行する |
| `exec format error` (ECS起動時) | ローカルがApple Silicon(arm64)でビルドしたイメージをx86_64環境で実行しようとしている | ビルドコマンドに `--platform linux/x86_64` オプションを追加して再ビルドする |
