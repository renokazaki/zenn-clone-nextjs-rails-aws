## この章でやること

backend ECS用のタスク定義を行います。

> 📍 **デプロイ全体フロー（現在地）**  
> ① VPC → ② サブネット → ③ IGW → ④ ルートテーブル → ⑤ セキュリティグループ → ⑥ RDS → ⑦ ECR → ⑧ コード準備 → **⑨ タスク定義** → ⑩ ALB → ⑪ サービス起動 → ⑫ CD自動化

### なぜタスク定義が必要か

ECRにイメージは置けましたが、「そのイメージをどう起動するか」はまだ決まっていません。タスク定義はdocker-compose.ymlに相当するもので、**どのイメージを使うか・どの環境変数を渡すか・ヘルスチェックの方法**などをまとめて宣言します。ECSはこの定義に従ってコンテナを起動します。

## タスク定義とは?

**タスク定義** とは、ECSにおけるコンテナ実行の設定内容を定義するものです。

ECRはコンテナを置いておく場所、ECSはコンテナを持ってきて起動する場所です。この「コンテナを持ってきて起動する」の具体的な方法を記述するのがタスク定義です。

1~複数個のコンテナの起動方法を設定するものであるので、開発環境における **docker-compose.yml** に相当するもの、考えると分かりやすいと思います。

## ECSタスク実行用IAMロールの作成

タスク定義の事前準備として、ECSタスクを実行するIAMロールの作成を行います。

検索窓からIAMにアクセスし、サイドバー「アクセス管理 > ロール」にアクセスしてください。

![](https://static.zenn.studio/user-upload/9c1eaebd5208-20230817.png)

「ロールを作成」ボタンをクリックし、以下の通り入力して「次へ」ボタンをクリックしてください。

| 項目 | 値 |
| --- | --- |
| 信頼されたエンティティタイプ | AWSのサービス |
| ユースケース | （プルダウンフォームから）Elastic Container Service |
| 択一選択肢 | Elastic Container Service Task |

![](https://static.zenn.studio/user-upload/0dfa9133601e-20230817.png)

↓

検索フォームを用いて、以下ふたつの許可ポリシーを検索してチェックボックスにチェックを入れ、「次へ」ボタンを押してください。

- **AmazonEC2ContainerRegistryReadOnly**
	- ECRからイメージをプルする権限
- **AmazonECS\_FullAccess**
	- ECSタスクを実行する権限
- **CloudWatchFullAccess**
	- CloudWatchでサーバーログを閲覧する権限

IAMロールの作成が完了したら、タスク定義を始めていきます。

検索窓から「Elastic Container Service」にアクセスし、サイドバーから「タスク定義」にアクセスしてください。

![](https://static.zenn.studio/user-upload/d7f60ee9a4a9-20230817.png)

↓

「新しいタスク定義の作成 > 新しいタスク定義の作成」を押下すると、タスク定義が開始します。

### 基本設定

| 項目 | 値 |
| --- | --- |
| タスク定義名 | zenn-clone-task-definition-backend |
| 起動タイプ | AWS Fargate |
| オペレーティングシステム/アーキテクチャ | Linux/x86\_64 |
| CPU | .25vCPU |
| メモリ | .5GB |
| タスクロール | ecsTaskExecutionRole |
| タスク実行ロール | ecsTaskExecutionRole |

> 💡 **なぜ `.25vCPU / .5GB` か**  
> AWS Fargateの最小スペックです。ポートフォリオ用途では十分で、コストも最小限（約$0.01/時間）に抑えられます。トラフィックが増えた場合はタスク定義を更新してスケールアップできます。

> 💡 **タスクロールとタスク実行ロールの違い**  
> **タスク実行ロール**はECSがECRからイメージをpullしたりCloudWatchにログを書き込んだりするための権限。**タスクロール**はコンテナ内のアプリがAWSサービスを呼び出すときの権限。今回は同じ `ecsTaskExecutionRole` を使いまわしています。
